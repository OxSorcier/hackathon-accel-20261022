# Hackathon delivery language

Received from Erwan on 22 October 2026. Applies to this project and the reusable hackathon harness.

Use English for every authored hackathon deliverable: UX/UI, Figma screens and flows, diagrams, mockups, image-generation text, navigation, forms, accessibility labels, loading/empty/error states, agent responses, example questions, README and supporting documentation, websites, slides, captions, demo narration, videos, and submission material. A French conversation or French source does not select French for the product. A later explicit instruction from Erwan can select another language.

Keep original source quotations, proper names, business records, native IDs and immutable historical evidence intact. Translate explanatory copy and label translations of quoted material. Preserve the distinction between synthetic data, proposed behavior, tested behavior and observed integration.

Use the same English terms across the app, design files, media and README. Recheck layout after translation, including narrow viewports and longer error messages. Check rendered text and agent output, not only the static label dictionary. A French-only current build remains pending until its English version is integrated and verified.

## Shared UI terms

| Meaning | English copy |
| --- | --- |
| Product workspace | Signals & Decisions |
| Pending human decision | Needs decision |
| Work underway | In progress |
| Finished work | Completed |
| Recurring monitoring | Watches |
| Nature of impact | Risk / Opportunity / Mixed impact |
| Unestablished fact or relationship | Needs verification |
| Commercial lead | Needs qualification |
| Versioned suggestion | Proposal |
| Outdated proposal | Stale proposal |
| Explicit test context | Synthetic data |
| Design target | Design proposal |
| Human confirmation | Confirm approval |
| Non-executing outcome | Approval recorded. No purchase or transfer executed. |
